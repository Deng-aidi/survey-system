## 6. 端到端联调测试记录

上述 78 条为 API 层手工测试。浏览器端完成了完整的"创建 → 填写 → 统计"闭环流程，验证前端与后端集成无误。

### 6.1 测试环境

- 浏览器：Chrome 最新版
- 后端：本地 `node server.js` + MongoDB 运行中
- 前端：Express `static` 托管的静态资源（Pico.css + 原生 JS）

### 6.2 完整闭环流程

| 步骤 | 操作 | 页面/接口 | 预期结果 |
|:-:|---|---|---|
| 1 | 访问 http://localhost:3000/ | index.html | 登录页正常显示，含登录/注册 Tab 切换 |
| 2 | 注册新用户 → 登录 | Auth POST /auth/register + /auth/login | 注册成功切回登录 Tab，登录成功跳 surveys.html |
| 3 | 创建问卷 | Survey POST /api/surveys | 列表出现新问卷，状态 draft |
| 4 | 添加 4 道题（单选/数字/多选/文本） | Question POST /api/surveys/:id/questions × 4 | edit.html 每加一道题实时刷新，order 自动递增 |
| 5 | 配置跳转规则 | Question PATCH .../jump_rules × 2 | 单选 other→null（跳到结束），多选 includes apple→null |
| 6 | 发布问卷 | Survey PATCH /api/surveys/:id/status {status:'open'} | 状态变为 open，edit.html 进入只读模式 |
| 7 | 复制填写链接 | surveys.html 复制按钮 | 剪贴板含 `/fill.html?token=xxx` |
| 8 | 打开填写页（另一个浏览器 tab 匿名） | Fill F1 GET /api/surveys/by-token/:token | 问卷内容正常显示，不要求登录 |
| 9 | 逐题填写（Q1 选 "other"） | Fill F2 × 1 + F3 | 跳过后 3 题，直接提交成功，submission_id 显示 |
| 10 | 再填一份（全部作答） | Fill F2 × 4 + F3 | 完整提交 4 题，DB 有 user_id 或 null |
| 11 | 查看统计 | Stats T1 GET /api/surveys/:id/stats | 统计页 2 份提交，单选 other=1 male=0，数字 avg=xxx，多选 apple=1（被跳过那份不出现） |

### 6.3 关键验证点

- **跳转规则生效**：Q1 选 "other" 后直接跳到结束，前端完全依赖后端返回的 `next_question_id`，未自行解释规则。
- **空答案不入 answers**：第二步填写时跳过非必答的文本/数字题，F3 重放正确识别，DB submission 的 answers 数组只含 4 条（答了的），统计 answer_count 正确反映。
- **版本冲突检测**：填写期间若创建者再改问卷（加题），提交时 409 提示刷新重填，不会静默污染新结构。
- **非匿名问卷访问控制**：非匿名问卷无 token 打开 fill.html 显示"请先登录"提示及登录链接。
- **统计零计数**：单选项 female=0、多选项 banana=0 均保留，前端进度条按 options 顺序渲染不会缺项。

## 7. 自动化集成测试执行报告 (Jest + Supertest)

除了上述 78 条手工 API 测试外，为了验证系统的持续可运行性，项目引入了 **Jest + Supertest** 自动化测试框架。当前共 **5 个测试文件 / 42 条用例**，覆盖第一阶段全部核心链路 + 第二阶段的题库、快照、结构锁、共享、跨卷统计，以及单卷统计 T1/T2、F2 单题校验与 F3 校验失败分支。

### 7.1 环境隔离说明

- **独立数据库**：测试运行时强制连接 `survey_system_test` 数据库，`beforeAll` 和 `afterAll` 会执行 `dropDatabase()`，确保每次测试环境纯净，**绝不污染开发业务库**。
- **服务复用**：通过 `require('../server')` 复用 Express App 实例，由 Supertest 模拟真实 HTTP 请求，不需要监听 3000 端口。
- **串行执行**：`jest --runInBand`，避免并发测试抢 MongoDB 连接。

### 7.4 核心回归用例说明（第二阶段）

**快照与结构锁**（survey-snapshot.test.js）：
- 从题库 v1 加入 → `source_question_id = 题库 v1 _id`、`source_version = 1`、`schema_hash` 非空；
- 发布后再调 `from-library` → 409 SURVEY_STRUCTURE_LOCKED；
- 已发布问卷 `PATCH /status {status:"draft"}` → 409 CANNOT_REVERT_TO_DRAFT（open 或 closed 后都不能回退）；
- **不同版本可同卷同时加入**（v1 和 v2 来源不同，不触发 DUPLICATE_QUESTION）。

**跨卷统计分叉防污染**（question-stats.test.js）：
- 同一 root 的不同快照（草稿期本地改写过题面）有不同 `schema_hash` → 分进独立 `by_schema_group` 卡片，`representative_version` 取链内最小版本；
- 他人创建的问卷**无论是否匿名**都被剔除，`excluded_surveys_count` 正确计数；
- 多版本同卷：同一张问卷里引用 v1 和 v2，两次提交 → `answer_count=2`（按提交文档计数，一人同时答 v1/v2 只算 1），但 `option_counts` 合并两版本答案。

**同卷重复拦截**（survey-snapshot + question-sharing + question-stats）：
- 新规则：`source_question_id === 题库题 _id` 即命中，同版本 400；
- 历史兼容：question-sharing 第 8 条直接向 Survey 写入一份"遗留同源快照"，验证 usages 仍能返回 2 条；
- 统计第 10 条在历史兼容场景下仍正确：`surveys=1`、`answer_count=2`、选项计数不翻倍。

**共享列表不含自己**（question-sharing）：
- `GET /api/questions?includeShared=true` 中，自己创建的共享题**按创建者身份**在默认列表返回（"我的"视角），但 `GET /api/questions/shared` 专门过滤 `creator_id !== 当前用户`（"共享给我"视角）。前端题库页两个 Tab 正确区分。
