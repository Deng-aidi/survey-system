# 系统说明

本文档是项目的整体导览：说明系统目标、两个阶段各自的核心能力、代码目录划分、可访问的页面入口以及本地运行方式。字段级 Schema 与算法细节请分别查阅《数据库设计.md》《关键逻辑说明.md》《API说明.md》。

---

## 1. 项目目标

本系统是一个基于 **Node.js + Express + MongoDB（Mongoose ODM）** 的在线问卷系统，覆盖「出题 → 发布 → 填写 → 统计」的完整闭环。

- **第一阶段**：实现问卷填写闭环。支持四种题型、可配置跳转、路径重放二次校验与零计数统计，重点解决「客户端不可信」「被跳转合法绕过 ≠ 漏答」这两个真实业务难点。
- **第二阶段**：在第一阶段闭环之上做**题库化**。题目从「问卷内嵌」升级为「独立题库 + 物化快照」，引入版本链、结构锁定、共享授权与跨问卷统计，解决「同一道题被多份问卷复用后如何安全演进、如何聚合统计」的问题。

前端保持零构建：原生 HTML + 原生 JS + Pico.css（CDN），后端为单一 Express 服务，静态资源与 API 同源部署。

## 2. 核心功能（第一阶段）

| 功能 | 说明 |
|---|---|
| 四种题型 | `single_choice` / `multiple_choice` / `text` / `number`，每种题型有独立校验规则：数字题 `min/max/integer`、多选题 `min_choices/max_choices`、文本题 `min_length/max_length` |
| 可配置跳转 | 每道题可配置多条跳转规则，六种 operator（`equals` / `includes` / `gte` / `lte` / `eq` / `between`），命中后跳到指定题或直接结束 |
| 路径重放二次校验（F3） | 提交时后端从第一题开始重放整个填写路径，区分「被跳转规则合法绕过」与「真漏答必答」，客户端结果不可信 |
| 零计数统计 | 统计按 `options` 顺序遍历，未出现过的选项返回 `count: 0` 而不是缺失，前端进度条不会缺项 |
| 发布前校验 | `draft → open` 时校验全部跳转规则：引用存在性、只允许向前跳、DFS 环检测 |
| `__v` 版本冲突检测 | 填写期间问卷结构被修改（`__v` 变化）时，提交返回 409，要求刷新后重填，避免静默污染新结构 |

## 3. 核心功能（第二阶段）

| 功能 | 说明 |
|---|---|
| 题库版本链 | 独立 `questions` 集合，题目按 `root_id / parent_id / version` 组织。任何结构修改都生成新版本文档，旧版本永不 UPDATE / DELETE，`{root_id, version}` 唯一索引防并发撞号 |
| 问卷快照 | 从题库加入问卷时做**物化深拷贝**，写入本地新 `_id`，并记录 `source_question_id` / `source_version` / `snapshot_at` / `schema_hash`。改题库不影响已发布问卷与旧答卷 |
| 结构锁定（structureLock） | `published_at || status !== 'draft'` 即锁定；已发布/已关闭问卷不能加题、删题、改跳转、从题库加题；已发布问卷也不能回退 draft（409 `CANNOT_REVERT_TO_DRAFT`） |
| 共享与引用追踪 | 题库题支持 `is_shared`（公开给全站）与 `shared_with`（定向共享）；`usages` 接口反查某道题被哪些问卷引用 |
| 跨问卷统计 | `GET /api/questions/:id/stats` 聚合引用该题的所有问卷；按 `schema_hash` 分组，相同结构合并、本地改写过的题面独立成组；他人问卷一律剔除并计入 `excluded_surveys_count` |

关键取舍：快照是**深拷贝**而非引用指针，所以「题库题改了，旧问卷不变」；跨卷统计只统计**自己创建的**问卷，是主动的隐私收紧，不是遗漏。

## 4. 目录结构

```text
├── server.js                 # Express 入口：中间件、路由挂载、静态资源、404 与全局错误兜底
├── config/
│   └── db.js                 # Mongoose 连接封装
├── middleware/
│   ├── auth.js               # JWT 强制鉴权（Bearer Token）
│   ├── optionalAuth.js       # 条件鉴权（填写模块用：登录可选）
│   ├── ownership.js          # 创建者身份校验（问卷归属）
│   └── structureLock.js      # 已发布问卷的结构锁定拦截
├── models/
│   ├── User.js               # 用户（bcrypt 哈希 + comparePassword）
│   ├── Question.js           # 题库题 + root_id/parent_id/version 版本链 + 共享字段
│   ├── Survey.js             # 问卷 + questions[] 快照数组 + published_at + 级联删除
│   └── Submission.js         # 提交记录，answers[] 冗余 question_type
├── routes/
│   ├── auth.js               # 注册 / 登录 / 当前用户
│   ├── surveys.js            # 问卷 CRUD + 题目管理 + 单卷统计（T1/T2）
│   ├── fill.js               # 按 token 填写：F1 取卷 / F2 单题校验 / F3 提交
│   └── questions.js          # 题库 CRUD + 版本链 + 共享 + usages + 跨卷统计
├── utils/
│   ├── jumpResolver.js       # 六种 operator 匹配 + 下一题解析
│   ├── questionValidator.js  # 答案校验 + 题目配置校验 + 发布前跳转校验
│   └── schemaHash.js         # 题面指纹（type/options/validation 规范化 MD5）
├── public/                   # 纯 HTML + 原生 JS 前端（Pico.css CDN）
├── tests/                    # Jest + Supertest（5 个文件 / 42 条用例）
└── docs/                     # 设计与测试文档
```

## 5. 访问地址

| 路径 | 说明 |
|---|---|
| http://localhost:3000/ | 登录/注册页 |
| http://localhost:3000/surveys.html | 我的问卷列表 |
| http://localhost:3000/edit.html?surveyId=xxx | 问卷编辑器 |
| http://localhost:3000/fill.html?token=xxx | 填写页 |
| http://localhost:3000/stats.html?surveyId=xxx | 统计页 |
| http://localhost:3000/question-bank.html | 题库页（第二阶段：建题 / 版本 / 共享 / 跨卷统计） |
| http://localhost:3000/api/health | 后端健康检查 |

填写链接也可用需求文档中的短路径 `http://localhost:3000/survey/:token`，服务端会 302 重定向到 `fill.html`。

## 6. 本地运行

### 环境要求

- Node.js 18+
- MongoDB 5+（本地默认端口 27017）

### 启动步骤

```bash
# 1. 安装依赖
npm install

# 2. 复制环境变量并编辑（主要是 JWT_SECRET）
cp .env.example .env

# 3. 启动 MongoDB
# Windows 服务：net start MongoDB
# 或直接：mongod --dbpath ./data

# 4. 启动服务
npm run dev     # 开发
npm start       # 生产

# 5. 运行自动化测试
npm test
```

### 测试隔离

自动化测试强制连接独立数据库 `survey_system_test`（`beforeAll` / `afterAll` 会 `dropDatabase()`），**不会污染业务库** `survey_system`。测试以 `jest --runInBand` 串行执行，避免并发抢连接。
