# 第二阶段数据库与接口改造设计草案

> 版本：v1.1（M7 收尾修复）　日期：2026-10-28
> 前置约束：**不推倒重做**。第一阶段的问卷、答卷、填写（F1/F2/F3）与统计（T1/T2）主链路保持可用。

---

## 0. 已拍板的设计决策

| # | 决策点 | 结论 |
|:-:|---|---|
| 1 | 共享权限 | 共享只授予"读 + 使用"，**不授予编辑权**；只有创建者能生成新版本 |
| 2 | 题库分组（`question_banks`） | **本期不实现**，后置 |
| 3 | 结构锁定时机 | `published_at \|\| status !== 'draft'` 即锁定；**禁止 closed → draft 回退** |
| 4 | 已加入题目升级版本 | **不支持**；只在"加入问卷时选择版本"，之后不随题库升级 |
| 5 | 旧数据回填 `published_at` | **不做回填**，依靠 `status !== 'draft'` 判定旧问卷锁定 |

### 0.1 设计原则

| 原则 | 含义 |
|---|---|
| 快照制 | 问卷里的题是物化副本，题库里的题是模板；模板改版不影响已有副本 |
| 追加式版本 | 版本链只增不改不删，历史版本永远可查 |
| 旧数据零迁移 | 新字段全部可空，旧文档天然按"独立内嵌题"处理 |
| 主链路零改动 | F1/F2/F3 与 T1/T2 不查询题库集合，继续只读问卷快照 |

## 1. 新增 `questions` 集合（题库）

### 1.1 Schema

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|:-:|---|---|
| `_id` | ObjectId | 是 | 自动 | 版本节点唯一标识 |
| `creator_id` | ObjectId ref User | 是 | — | 创建者，只有他能编辑 |
| `root_id` | ObjectId | 是 | 自身 `_id` | 版本链根节点 |
| `parent_id` | ObjectId \| null | 是 | null | 上一版本；根版本为 null |
| `version` | Number | 是 | 1 | 链内序号，从 1 递增 |
| `type` | String enum | 是 | — | single_choice / multiple_choice / text / number |
| `title` | String ≤200 | 是 | — | 题干 |
| `options` | `[{_id, label, value}]` | 否 | `[]` | 仅 choice 题使用 |
| `validation` | Mixed | 否 | `{}` | min/max/integer、min_length/max_length、min_choices/max_choices |
| `is_shared` | Boolean | 是 | false | 公开给所有登录用户 |
| `shared_with` | [ObjectId] | 是 | `[]` | 定向共享给指定用户 |
| `archived_at` | Date \| null | 否 | null | 软归档，不物理删除 |
| `created_at` / `updated_at` | Date | 是 | timestamps | — |

### 1.2 题库题刻意不存三个字段

| 字段 | 原因 |
|---|---|
| `order` | 属于"在某份问卷里的位置"，跨问卷无意义 |
| `required` | 属于"在某份问卷里是否必答"，跨问卷无意义 |
| `jump_rules` | 规则的 `targetQuestionId` 引用问卷内本地题的 `_id`，跨问卷无意义 |

结论：题库承载**题面语义**，问卷承载**编排语义**。

### 1.3 索引

| 索引 | 类型 | 用途 |
|---|---|---|
| `{root_id: 1, version: 1}` | **唯一** | 版本链防重；并发撞号时捕获 E11000 重试一次 |
| `{creator_id: 1, updated_at: -1}` | 普通 | "我的题库"列表 |
| `{is_shared: 1}` | 普通 | 共享题筛选 |
| `{shared_with: 1}` | 普通（多键） | "共享给我的"查询 |

### 1.4 版本链规则

- 首版：`root_id = 自身 _id`、`parent_id = null`、`version = 1`；
- 新版本：`root_id` 继承根、`parent_id = 来源版本`、`version = 链内最大值 + 1`；
- 恢复旧版不是回滚，而是"用旧版内容再生成一个新版本"，`parent_id` 指向当前链尾；
- 任何路径都不 `UPDATE` / `DELETE` 覆盖旧版本文档。

### 1.5 共享语义

- 可读 = 创建者 ∪ `is_shared = true` ∪ `shared_with` 含当前用户；
- 可写 = **仅创建者**；
- 共享不复制数据，双方引用同一条版本链，各自在问卷里生成各自的快照。

## 2. `surveys.questions` 快照改造

### 2.1 新增字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|:-:|---|
| `source_question_id` | ObjectId ref Question | null | 来源题库题；**null = 独立内嵌题**（旧数据即此状态） |
| `source_version` | Number | null | 生成快照时的题库题版本号 |
| `snapshot_at` | Date | null | 快照生成时间 |

`surveys` 顶层新增：

| 字段 | 类型 | 默认 | 说明 |
|---|---|:-:|---|
| `published_at` | Date \| null | null | 首次发布时间；只写不清，作为结构锁定标志 |

### 2.2 必须保留内嵌题的本地 `_id`

`submissions.answers[].question_id` 与 `jump_rules.targetQuestionId` 引用的都是内嵌子文档 `_id`。若换成题库题 `_id`，旧答卷与旧跳转规则全部失效。因此：

- 内嵌题继续使用自己的 `_id`（快照 = 深拷贝出的新文档，不是指针）；
- `options` 可重新生成 `_id`，但 `value` 必须原样保留。

### 2.3 从题库加入问卷（快照流程）

```
校验对题库题有读权限
  → 深拷贝 type/title/options/validation（options 重生成 _id，value 原样）
  → 生成新的本地 _id，order = questions.length，required 取请求值，jump_rules = []
  → 写入 source_question_id / source_version / snapshot_at
  → survey.save()
```

### 2.4 新增索引

| 索引 | 用途 |
|---|---|
| `{'questions.source_question_id': 1}` | 反查题目被哪些问卷使用 |

## 3. 旧功能兼容性说明

| 对象 | 影响 | 说明 |
|---|---|---|
| 旧问卷（无 source 字段） | 无 | 读出即 null，按独立内嵌题处理；draft 编辑路径不变 |
| 旧答卷 | 无 | `answers[].question_id` 仍指向内嵌 `_id`，快照保留本地 `_id` |
| F1/F2/F3 | 无 | 只读 `surveys.questions`，不 join `questions` 集合 |
| T1/T2 统计 | 无 | 仍按 `survey_id + 本地 question_id` 聚合 |
| 旧索引 | 无 | 新索引均为追加式；唯一索引只建在空的新集合上 |
| 已有 16 个端点 | 无 | 全部保留（除下方唯一一处收紧） |

**唯一行为变化**：已发布问卷的"加题 / 改跳转 / 从题库加入"由允许变为拒绝（需求三要求）。锁定判定：

```js
isStructureLocked = !!survey.published_at || survey.status !== 'draft'
```

取"或"是为让旧数据不回填也能被锁定。同时禁止 `closed → draft` 回退。

| HTTP | code | 含义 |

## 5. 需求三、需求四的代码级拦截

### 5.1 需求三：已发布问卷不可改题

1. **中间件硬拦截**：新增 `middleware/structureLock.js`，挂在三个结构变更端点（加题 / 改 jump_rules / from-library）之后、业务逻辑之前，返回 `409 SURVEY_STRUCTURE_LOCKED`；
2. **发布写标志**：`PATCH /:surveyId/status` 首次 `draft → open` 时写入 `published_at`，与 status 同一次 `save()`；
3. **双保险**：快照制保证改题库不影响已发布问卷，锁定中间件保证不能直接改问卷结构；
4. **前端配合**：非 draft 时禁用加题/跳转编辑并提示，后端仍是最终防线。

### 5.2 需求四：题目修改历史

| 操作 | 允许端点 | 禁止行为 |
|---|---|---|
| 改题面/选项/校验 | `POST /:id/versions` | `PATCH` 改结构 → 400 |
| 恢复旧版 | `POST /:id/restore` | 覆盖旧版本 |
| 删除 | 软归档 `archived_at` | 物理删除 |
| 共享设置 | `PATCH /:id` | 不产生新版本 |

版本不丢的保证：新版本 = 新文档；`{root_id, version}` 唯一索引 + E11000 重试；所有响应带 `{question_id, root_id, parent_id, version}`；`GET /versions` 升序返回。

## 6. 跨问卷统计设计（M4）

1. 由 `questionId` 取 `root_id`，得到版本链（默认只取该版本）；
2. 反查问卷：`Survey.find({'questions.source_question_id': {$in: versionIds}})`；
3. 聚合答卷：`$match(survey_id, answers.question_id)` → `$unwind` → 分组计数；
4. 输出全局汇总 + 按问卷拆分 + 按版本拆分。

默认 `includeVersions=false`；为 true 时合并整条链但**按版本分组返回**，不做跨版本求和，避免不同版本同 `value` 语义漂移被误合并。

### 8.2 收尾增强

- **禁止已发布问卷回退 draft**：`PATCH /:surveyId/status` 在状态枚举校验后增加判断；当 `status === 'draft' && req.survey.published_at` 时返回 `409 CANNOT_REVERT_TO_DRAFT`。`open/closed → draft` 均拒绝；从未发布过的 `draft → open` 正常。
- **跨卷统计按问卷去重**：`GET /:questionId/stats` 构建 mappings 时，每份问卷只取第一个命中快照，避免同一问卷重复引用同一题导致选项计数翻倍。
- **题库弹窗包含共享题**：编辑页请求改为 `GET /api/questions?includeShared=true`，并增加“来源”列展示“我的 / 共享”。
- **只读状态禁用元信息**：问卷已发布/已锁定时，前端禁用 `#e-deadline` 与 `#btn-save-settings`，提示文案为“问卷已发布/已锁定，题目与结构不可修改”。后端 `PATCH /api/surveys/:surveyId` 本轮仍允许修改元信息，结构锁定仅作用于加题、改跳转、from-library。

### 8.3 统计口径与快照语义

- **跨问卷统计口径**：只统计“题主自己创建的、引用了这道题的所有问卷”。同事创建的问卷（无论是否匿名）不进入聚合，统一计入 `excluded_surveys_count`。
- **快照语义**：修改题库题不会影响已发布的旧问卷与旧答卷；问卷内保存的是物化快照。需要使用新版本时，应新建问卷并重新从题库引用。
- **结构锁定**：`published_at || status !== 'draft'` 即锁定；已发布问卷不能回退 draft，避免出现“既不能填写也不能修改”的状态。

### 8.4 测试结果

当前测试：`5 suites / 38 tests passed`。新增覆盖包括共享列表不含自己、同一问卷多次引用 usages 返回多条、新版本继承共享状态、已发布问卷不能回退 draft、同一问卷重复引用统计不翻倍。
